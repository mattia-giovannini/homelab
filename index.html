# Infrastructure I actually run, at home.

A small self-hosted lab — GitOps-managed Kubernetes, runtime security, observability — that doubles as a testbed for a different question: what does it take to give an agentic AI safe, scoped access to infrastructure that actually matters?

$ cat stack.json

Raspberry Pi

A Pi 5 is the main node; a Pi 2 on the side runs DNS failover and the Tang server the encrypted disks depend on.

Debian

Trixie on every machine — stable and boring, exactly what you want underneath a homelab.

k3s

Two-node cluster, arm64 Pi plus an amd64 iMac. Taints and priority classes decide what runs where, and what gets evicted first on an 8 GB node.

Flux

GitOps: the cluster is whatever the repository says. Every change is a reviewed commit, images are pinned by digest, Renovate proposes the updates.

SOPS + age

Secrets live encrypted next to the manifests they belong to; the key never touches Git, and CI fails on anything that looks like plaintext.

Traefik

Ingress for every service, with cert-manager issuing from an internal CA and forward-auth in front of each admin UI.

Pocket ID

Passkey-only OIDC provider. No passwords on the admin interfaces — oauth2-proxy and forward-auth check the session first.

Falco

Syscall-level runtime detection. Exceptions are scoped to one container and one command, never a whole rule switched off.

VictoriaMetrics

Metrics, plus VictoriaLogs for logs — picked because memory is the scarce resource here. Alertmanager routes what matters to email.

Grafana

Dashboards over all of it. Usually the first tab I open when something feels slow.

Cloudflare Tunnel

The only public entry point, behind Cloudflare Access. The router forwards no ports; everything else is reached over Tailscale.

LUKS + Clevis/Tang

Data disks unlock at boot only when they can reach the Tang server on the home network. Stolen, they stay sealed.

Ansible

The hosts themselves as code — DNS, firewall, storage, k3s — plus nightly encrypted restic backups with consistent database snapshots.

Claude Code

How I do the infra work — through pull requests I review — and a sandboxed always-on instance that can read telemetry and nothing else.

$ cat agentic-ai.md

The lab exists to answer a practical question, not a hypothetical one: what does it take to give an AI agent safe, scoped access to infrastructure that actually matters?

My approach: define the boundary before the tool touches anything, and make the boundary something the infrastructure enforces rather than something the agent is asked to respect.

Concretely, the always-on Claude Code instance runs in its own namespace under the restricted Pod Security profile: read-only root filesystem, no capabilities, no Kubernetes API token. It can read the configuration repository with a token scoped to that one repository, and nothing can be pushed with it. It sees metrics and alerts through a small nginx proxy that allows a handful of GET endpoints and rate-limits them; the write and delete APIs behind it (series deletion, imports, silences) simply aren't reachable. Logs are deliberately out of reach, because they contain personal data. A NetworkPolicy lets it talk to DNS, the internet and that proxy, and nothing else on the LAN.

The agents that do change things work through pull requests: they prepare the commit, I approve every push, and Flux applies what was merged. Read-only where read-only is enough, scoped and supervised where it isn't, and always something I can audit afterwards in Git.

Everything here runs at home: a two-node k3s cluster (a Raspberry Pi 5 and an old iMac) and a Pi 2 for DNS failover and the Tang server. It's small on purpose — big enough to be useful, small enough that I still understand every piece of it.
